= 使用 NetApp Backup and Recovery 保护 ONTAP 卷工作负载
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
使用 NetApp Backup and Recovery 来保护和恢复您的 ONTAP 卷数据，并长期存档备份。您可以实施 3-2-1 策略，在两个不同的存储系统上保留三个源数据副本，并在云端保留一个副本。

为系统启用保护后，Backup and Recovery 将创建卷的块级永久增量副本。除了源卷之外，您还有：

* 源系统上的卷快照
* 其他 ONTAP 存储系统上的复制卷
* 对象存储中的卷的备份


image:diagram-321-overview-unified.png["显示备份文件如何作为快照存在于源系统上、作为复制卷存在于二级存储系统上，以及作为备份文件存在于对象存储中的图表。"]

3-2-1 方法提供以下优势：

* 多个数据副本可防止内部和外部网络安全威胁。
* 如果一种媒体发生故障，使用不同类型的媒体可以帮助您恢复。
* 您可以从现场副本快速恢复，如果现场副本受到损害，则可以使用异地副本。


必要时，您可以将整个_卷_、_文件夹_或一个或多个_文件_从任何副本恢复到同一个或不同的系统。



[[how-protection-for-ontap-volumes-works]]
== 保护 ONTAP 卷的工作原理

当您为 Cloud Volumes ONTAP 或本地 ONTAP 系统启用备份和恢复时，该服务将执行卷数据的完整基线传输。之后，所有传输都是增量传输：仅传输已更改和新区块，从而将网络流量降至最低。

备份和恢复使用 ONTAP SnapMirror 技术来保持副本同步。它会在源卷上创建快照，并将它们传输到复制和备份位置。备份到对象存储是基于 https://docs.netapp.com/us-en/ontap/concepts/snapmirror-cloud-backups-object-store-concept.html["NetApp SnapMirror云技术"^]构建的。

image:diagram-backup-recovery-general.png["该图显示了NetApp Backup and Recovery如何与源系统上的卷以及复制卷和备份文件所在的二级存储系统和目标对象存储进行通信。"]

此图显示了正在复制到 Cloud Volumes ONTAP 系统的卷，但您也可以将卷复制到本地 ONTAP 系统。

每种类型的副本都位于不同的位置：

* 快照存储在源系统的源卷上。
* _Replicated volumes_ 驻留在辅助存储系统上，该系统可以是 Cloud Volumes ONTAP 或本地 ONTAP 系统。
* _备份副本_位于您的云帐户或本地的对象存储中。控制台为每个集群创建一个对象存储。有关控制台如何创建和命名对象存储的详细信息，请参阅 link:concept-backup-to-cloud.html#where-backups-reside-in-object-store-locations["备份在对象存储位置的位置"]。



CAUTION: 请勿直接从存储系统或云提供商环境中管理或更改备份文件。此操作可能会损坏文件并导致不支持的配置。

要计划使用的副本和架构，请参阅 link:prev-ontap-protect-journey.html["规划 ONTAP 卷保护"]。



[[features]]
== 功能

*复制*

* 在ONTAP存储系统之间复制数据以支持备份和灾难恢复。
* 一次将多个FlexVol卷复制到辅助系统。
* 在两个系统之间使用带有预共享密钥 (PSK) 的原生 ONTAP 传输中加密。
* 在发生传输失败时依靠自我修复复制。
* 将已复制的卷还原到源系统或其他系统。


有关使用 Backup and Recovery 进行复制时不可用的 https://docs.netapp.com/us-en/data-services-replication/index.html["NetApp Replication"^]中的功能，请参阅 link:br-reference-limitations.html#replication-limitations-for-ontap-volumes["ONTAP卷的复制限制"]。

*备份到对象存储*

* 将卷的独立副本备份到低成本对象存储，从本地或云系统备份到公共或私有云。
* 将单个备份策略应用于群集中的所有卷，将不同的策略分配给具有唯一恢复点目标的卷，或创建适用于群集中所有未来卷的策略。请参阅link:prev-ontap-policy-manage.html["管理 ONTAP 卷的策略"]。
* 使用 DataLock 和勒索软件扫描保护备份免受删除和勒索软件的侵害。请参阅link:prev-ontap-policy-object-options.html#datalock-and-ransomware-protection-options["DataLock 和勒索软件保护选项"]。
* 将较旧的备份分层到归档存储以节省成本。请参阅 link:prev-ontap-policy-object-options.html#archival-storage-options["档案存储选项"]。
* 删除备份关系，以便您可以在保留其备份的同时停用源卷。
* 单个卷最多可保留 4,000 个备份。
* 使用静态 AES-256 位加密和传输中的 TLS 1.2 HTTPS 连接保护备份数据，或使用您自己的客户管理密钥，而不是默认的云提供商密钥。


*还原*

* 从本地快照、复制卷或对象存储中的备份还原特定时间点的数据。
* 将卷、文件夹或单个文件还原到源系统或其他系统，包括使用不同订阅或帐户或位于不同区域的系统。
* 当需要尽快提供对卷的访问时（例如在灾难恢复情况下），执行从对象存储到 Cloud Volumes ONTAP 或本地系统的卷的_快速还原_。
* 将块级别的数据直接还原到指定的位置，保留原始 ACL。
* 浏览或搜索文件目录以选择要还原的单个文件夹和文件。


有关还原选项，请参见link:prev-ontap-restore.html["恢复ONTAP卷工作负载"]。



[[supported-volumes]]
== 支持的卷

NetApp Backup and Recovery支持以下类型的卷：

* FlexVol读写卷
* FlexGroup卷（需要ONTAP 9.12.1 或更高版本）
* SnapLock Enterprise卷（需要ONTAP 9.11.1 或更高版本）
* 适用于本地卷的 SnapLock Compliance（需要 ONTAP 9.14 或更高版本）
* SnapMirror数据保护 (DP) 目标卷



NOTE: NetApp Backup and Recovery不支持FlexCache卷的备份。

有关 Backup and Recovery 支持的源系统、辅助系统、对象存储目标、还原目标和区域，请参阅link:br-start-sources-destinations.html["NetApp Backup and Recovery 中支持的备份和还原目标"]。如需了解其他要求和限制，请参阅link:br-reference-limitations.html["NetApp Backup and Recovery for ONTAP卷的已知限制"]。



[[cost-and-licensing]]
== 成本和许可

除了创建快照或复制卷所使用的磁盘空间外，您无需支付任何费用。云提供商的资源费用和 NetApp 的服务费用仅适用于备份到对象存储。

有关成本和许可选项的详细信息，请参阅link:concept-backup-to-cloud.html#cost["了解NetApp Backup and Recovery"]和link:br-start-licensing.html["设置许可"]。
