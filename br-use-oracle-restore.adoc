= 使用 NetApp Backup and Recovery 还原 Oracle 数据库工作负载
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
使用 NetApp Backup and Recovery 从快照、辅助存储上的复制备份或对象存储中存储的备份还原 Oracle 数据库工作负载。

.从这些位置恢复
您可以从不同的起始位置恢复数据库：

* 从主位置恢复（本地快照）
* 从二级存储上的复制资源恢复
* 从对象存储备份恢复


.恢复到这些点
您可以将数据库还原到其原始位置，也可以在其他注册主机（备用位置）上将其还原为新数据库。

* 恢复到原始位置
* 还原到备用位置（其他注册主机）




[[how-oracle-database-restore-works]]
== Oracle 数据库还原的工作原理

还原 Oracle 数据库工作负载时，将发生以下情况：

* 当您从本地快照恢复数据库时， NetApp Backup and Recovery会使用备份中的数据创建一个_新_资源。
* 从复制的存储恢复时，您可以将其恢复到原始位置。
* 当您还原到备用位置时，NetApp Backup and Recovery 会将源数据库的选定备份作为新数据库还原到另一个已注册的主机上。您需要指定目标主机和新数据库的名称。如果您不提供还原规范文件，Backup and Recovery 会自动计算目标主机上数据文件、控制文件和重做日志文件的位置。
* 从对象存储还原备份时，您可以将数据还原到源存储或本地ONTAP系统，然后从那里恢复数据库。




[[view-information-about-available-oracle-database-restore-points]]
== 查看有关可用的 Oracle Database 还原点的信息

查看可用的还原点，包括 SCN 编号和关联的数据库化身。


NOTE: 每次使用 `RESETLOGS`选项打开数据库时，Oracle Database 都会创建一个新的数据库化身。NetApp Backup and Recovery 会在您查看还原点以及还原到特定 SCN 时列出相关的数据库化身。

.步骤
. 在 Backup and Recovery 菜单中，选择*清单*。
. 从NetApp Backup and Recovery菜单中，选择 *恢复*。
. 为 Oracle Database 工作负载选择*视图*。
. 选择“*数据库*”选项卡。
. 选择要查看其还原点的数据库的*操作*image:icon-action.png["操作图标"]图标，然后选择*查看保护详细信息*。
. 查看可用的还原点以及与每个还原点关联的 SCN 编号和数据库化身。




[[restore-an-oracle-database]]
== 还原 Oracle 数据库

根据您的需要，将 Oracle 数据库还原到特定时间点、特定系统更改编号 (SCN) 或最后一个正常状态。您也可以从快照还原数据库并跳过自动恢复过程，例如，如果您希望手动执行恢复。您可以使用数据库名称或特定筛选器搜索数据库。

*必需的 NetApp Console 角色* 备份和恢复超级管理员或备份和恢复还原管理员角色 https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["了解所有服务的NetApp Console访问角色"^]。

[[alternate-location-support]]
.开始之前
还原到备用位置时，请记住以下受支持和不受支持的还原方案：

*支持的备用位置还原方案*

* 将单个完整的 Oracle 数据库恢复到单个目标主机
* 恢复到特定时间点、特定 SCN 或最新备份
* 当所选恢复点所需的归档日志未包含在备份中时，使用外部归档日志目录


*不支持的备用位置还原方案*

* 仅表空间还原，包括还原 PDB 内的表空间
* 仅 PDB 还原到其他容器数据库（CDB）
* 从二级存储还原
* 从对象存储还原


[NOTE]
====
如果将 PDB 或表空间恢复到特定时间点或 SCN：

* 仅选择一个 PDB。时间点恢复与恢复多个 PDB 不兼容。
* `PDB$SEED` 不能选择用于时间点恢复。
* 控制文件还原不能与 PDB 或 PDB 表空间的时间点恢复相结合。
*  `SYSTEM`、 `SYSAUX` 和  `UNDO` 表空间无法选择。


====
.步骤
. 从NetApp Console菜单中，选择“保护”>“备份和恢复”。
. 从NetApp Backup and Recovery菜单中，选择 *恢复*。
. 从名称搜索字段右侧的下拉列表中，选择 *Oracle*。
. 输入要还原的数据库的名称或筛选要还原的数据库所在的数据库主机。
+
出现符合您的搜索条件的快照列表。

. 选择要恢复的数据库的“*恢复*”按钮。
. 选择恢复选项：
+
[role="tabbed-block"]
====
.恢复到特定时间点
--
.. 选择*恢复到特定时间点*。
.. 选择“下一步”。
.. 从下拉菜单中选择一个日期，然后选择*搜索*。
+
显示最接近指定日期和时间的快照。

.. 如果快照存储在多个位置，请选择要使用的源位置，并添加或查看位置详细信息。
.. 选择“下一步”。


--
.恢复到特定的系统变更号 (SCN)
--
.. （可选）请参考 <<查看有关可用的 Oracle Database 还原点的信息>> 查看可用的 SCN 和关联的数据库化身。
.. 选择*恢复到特定的系统变更号 (SCN)*。
.. 选择“下一步”。
.. 输入要用作还原点的 SCN，然后选择*搜索*。
+
将显示指定 SCN 的最近匹配快照。如果多个数据库化身与 SCN 匹配，则显示所有匹配的化身。

.. 如果多个数据库化身与搜索匹配，请选择具有正确化身的快照。
.. 如果快照存储在多个位置，请选择要使用的源位置，并添加或查看位置详细信息。
.. 选择“下一步”。


--
.恢复到最新备份（上次良好状态）
--
.. 选择*恢复到最新备份*。
.. 选择“下一步”。
+
此时将显示最新的快照。此还原操作使用所有可用的日志备份恢复上次正常状态。

.. 如果快照存储在多个位置，请选择要使用的源位置，并添加或查看位置详细信息。
.. 选择“下一步”。


--
.从快照还原，无需恢复
--
.. 选择*从没有恢复的快照中恢复*。
+
选择此选项意味着将从快照还原数据库，但会跳过恢复（不应用日志备份）。

.. 选择“下一步”。
+
显示可用的快照。

.. 从列表中选择一个快照，然后选择*下一步*。
.. 如果快照存储在多个位置，请选择要使用的源位置，并添加或查看位置详细信息。
.. 选择“下一步”。


--
====
. 选择恢复目标位置和设置：
+
[role="tabbed-block"]
====
.恢复到原始位置
--
.. 在*目标设置*部分，执行以下操作：
+
... 对于 RAC 数据库，选择要在其上运行还原的 RAC 节点。此选项仅适用于 RAC 数据库。
... 选择要还原的内容：
+
**** 选择*所有数据文件*以恢复整个数据库或容器数据库(CDB)。
**** 选择 *Pluggable databases (PDBs)* 从 CDB 恢复一个或多个 PDB，而不影响容器中的其他 PDB。然后从列表中选择 PDB。
**** 选择*可插拔数据库 (PDB) 表空间*（对于非 CDB 数据库显示为*表空间*）以恢复特定的 PDB 表空间。然后，选择 PDB 和表空间。


... （可选）启用 *控制文件* 选项以还原数据库控制文件。不能为 PDB 或 PDB 表空间的时间点或 SCN 恢复选择此选项。
... （可选）启用 *Change database state if needed for restore and recovery* 选项，以允许 Backup and Recovery 根据恢复类型管理数据库状态。
... （可选）启用 *强制就地恢复* 选项，以便在备份后添加新数据文件或在 LVM 磁盘组中添加、删除或重新创建 LUN 时执行就地恢复。这将覆盖外部文件检查；数据库恢复使用您选择的还原选项进行。
... 如果将数据库恢复到特定时间点或 SCN，并且归档日志不在配置的位置，请在 *指定外部归档日志文件位置* 字段中指定外部归档日志文件位置。输入以 `/`开头的文件系统路径或以 `+`开头的 ASM 磁盘组。使用文本输入字段旁边的“加号”和“减号”按钮添加或删除位置。在不执行恢复的情况下从快照还原时，此字段不会出现。
... （可选）启用*恢复后以读写模式打开数据库或容器数据库*选项，并选择与还原范围匹配的子选项（从无恢复的快照中还原时，这些选项不会出现）：
+
**** *All datafiles*：恢复后以读写模式打开数据库或容器数据库。
**** *PDBs or PDB tablespaces*：恢复后以读写模式打开可插拔数据库。
**** *非 CDB 表空间*：恢复后使表空间联机。




.. 在 *Prescripts and postscripts* 部分中，执行以下操作：
+
... *Prescript*：（可选）启用此选项并输入应在还原操作之前运行的脚本的完整路径以及脚本所需的任何参数。
... *后记*：可选地，启用此选项并输入应在恢复操作后运行的脚本的完整路径以及该脚本所采用的任何参数。
... 为脚本选择超时值。如果脚本无法在此时间段内执行，则还原仍将继续。




--
.恢复至备用位置
--
在其他注册主机上将数据库还原为新数据库。在开始之前，请先查看 <<alternate-location-support,支持和不支持的场景>>。

.. 在*目标设置*部分中，输入以下信息：
+
... *目标主机*：选择要在其中创建新数据库的注册主机。
... *目标数据库*：输入目标数据库的名称。默认情况下，名称以源数据库的名称开头，您可以对其进行编辑。
... *自定义目标数据库参数*：启用此选项可上传自定义还原规范文件以自定义目标数据库参数。
... *还原规范文件*：如果启用了*自定义目标数据库参数*选项，请提供还原规范文件以控制还原文件在目标主机上的位置。您可以下载默认还原规范文件并进行自定义，以更改身份验证和日志位置等目标数据库详细信息。
+
如果不提供还原规范文件，Backup and Recovery 会自动计算数据文件、控制文件和重做日志文件的位置。

... 如果将数据库恢复到特定时间点或 SCN，并且归档日志不在配置的位置，请在 *指定外部归档日志文件位置* 字段中指定外部归档日志文件位置。输入以 `/`开头的文件系统路径或以 `+`开头的 ASM 磁盘组。使用文本输入字段旁边的“加号”和“减号”按钮添加或删除位置。在不执行恢复的情况下从快照还原时，此字段不会出现。
... （可选）启用*恢复后以读写模式打开数据库或容器数据库*选项，并选择与还原范围匹配的子选项（从无恢复的快照中还原时，这些选项不会出现）：




--
====
. 选择*恢复*。
+
还原操作完成后，检查*清单*页面以确认新数据库已列出。如果未列出数据库，请刷新目标主机。
